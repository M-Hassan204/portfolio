About

Engineering Philosophy

I'm a Full-Stack .NET Developer based in Minya, Egypt. I build web applications where architecture, data integrity, and maintainability matter as much as feature delivery.

My approach is grounded in the belief that good software starts with clear thinking about the problem domain. I design systems around the data model and domain first — because a well-designed database schema and clean API contract will outlast any framework trend.

I focus on the full picture: designing relational schemas, building secure REST APIs with ASP.NET Core, and connecting them with clean React frontends. I use N-Layer Architecture, DTOs, service abstractions, and EF Core Code First migrations because they make code easier to reason about and safer to change.

01
Architecture first

Design the domain model, data layer, and API contract before writing business logic.

02
Data integrity by design

Validation at every layer — client, server, and database — not just the UI.

03
Maintainability over cleverness

Code should be readable, testable, and safe to change six months later.

ASP.NET Core MVC.NET 10EF CoreMulti-layer ValidationSQL Server

Clinic Appointment Booking System

An ASP.NET Core MVC application for managing doctor–patient appointment scheduling. The standout engineering is a three-layer validation system enforced simultaneously at client, server, and database levels — demonstrating how production applications protect data integrity regardless of how a request originates.

Three-Layer Validation Architecture

Layer 1
Client-Side

JavaScript date picker blocks Fridays, Saturdays, and past dates. Time picker constrains selections to valid 30-minute slots within clinic hours.

Layer 2
Server-Side

Controller validates day-of-week, time slot validity via TimeSpan, and queries the database for duplicate bookings on the same Doctor + Date + Time.

Layer 3
Database Level

Unique composite constraint on (DoctorId, AppointmentDate, AppointmentTime) — a guaranteed last line of defense even against concurrent requests.

Business Rules Enforced

  • Working days only: Sunday → Thursday
  • Clinic hours: 09:00 – 17:00
  • 30-minute time slots strictly enforced
  • No double-booking per doctor
  • Doctor-specific slot availability
  • DB unique constraint as final guard

Technical Stack

  • ASP.NET Core MVC / .NET 10 / C# 14
  • Entity Framework Core 10
  • SQL Server with EF Migrations
  • Razor Views + Bootstrap
  • EF Core Seed Data
  • Client + server validation

Engineering Outcome

A complete scheduling system that correctly enforces domain business rules at all three validation layers. Demonstrates a clear understanding of why client-side validation alone is insufficient — and how to design data integrity guarantees that hold under concurrent access or direct API calls.
